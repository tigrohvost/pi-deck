# Ускорение обработки контекста без телефона — 17 октября 2026

Телефон во время работы недоступен. Изменения проверяются локально на полном
GGUF каждой модели и том же исходном Prism `842b188` с патчами
`pideck-prism1`. Стенд — Intel Core i7-1255U, Linux x86_64, Clang 19.0.1,
четыре CPU-потока;
числа ниже не являются замерами Android.

## Изменения

- **Bonsai 2 4B/9B сохраняют системный префикс и схемы инструментов.** Первый
  запрос вычисляет префикс и сохраняет состояние слота в приватном кэше
  приложения. После перезапуска модели или новой сессии расширение
  восстанавливает подходящий снимок перед основным запросом. Ключ включает
  SHA-256 весов, системное сообщение и контракт запроса. Возможность включена
  только для двух закреплённых артефактов, Prism `842b188` и контекста 4096.
  Дисковые снимки отделены от повторного использования живых рекуррентных
  чекпоинтов между сессиями: последнее для Prism не включается.
- **Финальный ответ после инструмента сохраняет живой кэш.** Для этих же
  артефактов `tool_choice: auto → none` не меняет отрендеренный промпт и теперь
  не вызывает полный пересчёт. Другой набор инструментов, системное сообщение
  или шаблон остаётся причиной для проверки отдельного снимка или полного
  пересчёта.
- **Ошибка записи снимка не удваивает prefill.** Если префикс уже успешно
  вычислен, отказ записи на диск оставляет его доступным следующему запросу
  в живом слоте. Это исправление применяется ко всем моделям с включёнными
  снимками, включая основной движок.
- **Подготовка кэша учитывает отмену запроса.** HTTP-запросы подготовки и
  восстановления используют сигнал отмены Pi. Прерванная подготовка не
  помечается как готовая история для следующего хода.

Изменения восстанавливают вычисленное состояние контекста. Они не являются
замером скорости декодирования новых токенов. При первом использовании,
удалённом кэше или новом системном промпте префикс нужно вычислить.

## Проверка на настоящем движке

[`probe_prefix_cache.mjs`](../tools/probe_prefix_cache.mjs) загружает настоящее
расширение через jiti из Pi 0.82.1. Перед запуском он проверяет SHA-256 и размер
GGUF, поднимает отдельный сервер с аутентификацией на loopback и приватным
каталогом снимков. Промпт ограничен системной инструкцией и одним инструментом
`read`; это не полный системный промпт агента Pi.

Каждая серия сначала создаёт снимок, затем чередует полный пересчёт и
восстановление в порядке ABBA. Перед каждым из этих четырёх запросов сервер
полностью перезапускается. Время запроса включает восстановление снимка,
обработку промпта и генерацию, но исключает запуск Node и загрузку модели.
Температура — 0, seed — 7, лимит — 128 токенов; обрезанный ответ считается
ошибкой. Дополнительно сравниваются вызов `read`, ответ на синтетический
результат инструмента и запрос с переписанной историей в той же сессии.
Инструмент не исполняется.

| Модель / сценарий | Полный пересчёт | С кэшем | Ускорение |
| --- | ---: | ---: | ---: |
| 4B, запрос после перезапуска, среднее двух образцов | 65,08 с | 7,55 с | 8,62× |
| 4B, финальный ответ после инструмента | 74,27 с | 4,71 с | 15,77× |
| 4B, запрос после переписывания истории | 65,36 с | 6,46 с | 10,11× |
| 9B, запрос после перезапуска, среднее двух образцов | 123,29 с | 12,41 с | 9,94× |
| 9B, финальный ответ после инструмента | 145,51 с | 13,58 с | 10,72× |
| 9B, запрос после переписывания истории | 126,62 с | 14,63 с | 8,66× |

Контрольный ответ `CACHE_OK` содержит 3 выходных токена, `CACHE_TOOL_OK` — 4.
В этих коротких ответах преобладает время prefill; коэффициенты не описывают
ускорение длинной генерации. Снимок ограниченного префикса занимает
61 840 744 байта (около 59 MiB).

Для запросов после перезапуска сохраняется 279 токенов: сервер пересчитывает
26 вместо 305. В финальном ответе после инструмента обе модели переиспользуют 333
токена и пересчитывает 21 вместо 354. Все 22 нативные проверки прошли. Во всех парах совпадают
текст, рассуждение и имя/JSON-аргументы вызовов; случайные ID вызовов исключены
из сравнения. Это ограниченная проверка корректности кэша, а не общий тест
качества модели.

Полные ответы, счётчики кэша, длительности отдельных запросов, SHA сборки и
весов, происхождение исходников и результаты проверок APK сохранены в
[отчёте стенда](../benchmarks/out/bonsai2-prefix-cache-host-2026-10-17.json).

## Проверки приложения

Пройдены 239 JVM-тестов, 145 Python runtime-тестов, загрузка 12 расширений и
проверки их 10 инструментов, два интеграционных теста протокола Pi. Проверены
отказ записи снимка, отмена подготовки, несовпадение SHA/движка/контекста и
инвалидация кэша при изменении схемы или системного сообщения. Gradle
`testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest` прошёл;
lint: 0 ошибок, 13 предупреждений. Контракт benchmark-suite: 28 задач.
Инструментальные тесты собраны, но без телефона не запускались.

Для повторения проверки нужен Linux CPU `llama-server`, собранный из
[закреплённого Prism и двух патчей](../third_party/prism/README.md), исходный
GGUF из каталога и установленный Pi 0.82.1:

```sh
node tools/probe_prefix_cache.mjs \
  /path/to/node_modules /path/to/llama-server \
  bonsai2-4b /path/to/Ternary-Bonsai-2-4B-PTQ1_0.gguf /tmp/4b-prefix.json
```

Для 9B используются `bonsai2-9b` и соответствующий GGUF. Необязательный
`--full-agent` подставляет более длинные инструкции и схемы из существующего
стенда `adb_runtime_experiments`; приведённые числа получены без этого флага.

Когда телефон станет доступен, нужна проверка полного промпта Pi в APK:
создание/восстановление снимка после остановки ядра, продолжение с инструментом,
смена системного промпта, отмена во время prefill и поведение под давлением
памяти. Статус моделей остаётся `CANDIDATE`.

Дополнение 19 октября: телефон подключён, проверка настоящего Pi-промпта
выявила и устранила дополнительный HTTP-таймаут подготовки кэша. Замеры,
ограничения проверки качества и результат сборки GitHub находятся в
[отдельном отчёте](agent-speed-2026-10-19.md).
