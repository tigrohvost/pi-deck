# Модели на SM-S918B: проверка 8 октября 2026

Для агентной работы основной кандидат остаётся **LFM2.5 2.6B QAD Q4_0**.
Меньшая LFM2.5 1.2B QAD заметно быстрее, но в проверенных сценариях чтения и
редактирования подменяет вызовы инструментов текстом. Spark-X2.5 1.7B выполняет
исправление при включённом reasoning и достаточном лимите ответа, но медленнее
основной LFM. Эти результаты не дают основания автоматически менять модель или
движок приложения.

## Условия и границы выводов

- Samsung SM-S918B, Snapdragon 8 Gen 2, 12 ГБ, Android 16, питание USB.
- COMSAT Audio и другие приложения продолжали работать. Пользователь явно
  выбрал продолжение с текущей нагрузкой. Потолки частот CPU менялись; это
  наблюдения на занятом телефоне, а не лабораторный рейтинг максимальной скорости.
- Отдельный сервер под `adb shell`, CPU, 8192 токена контекста, один слот,
  `--no-mmap`, decode: 5 потоков на ядрах 3–7, prefill: 8 на 0–7,
  batch 2048, ubatch 512. Это не запуск через UID приложения и полный Pi harness.
- Скорость: четыре ответа по 192 токена с `ignore_eos`, первый прогревочный
  отброшен, медиана остальных трёх. Разные токенизаторы и наличие reasoning
  ограничивают интерпретацию токенов/с; время законченной задачи приведено отдельно.
- Перед измерением ожидалась температура CPU/GPU не выше 65 °C. Строгий порог
  частот оказался недостижим при фоновой нагрузке; основные серии использовали
  `--min-headroom .01`, то есть практически только температурный порог. Начальные
  незавершённые попытки сохранены как `*-pilot*.json` и в итоговые медианы не входят.
- Все веса независимо проверены SHA-256 на телефоне. В измеренных скоростных
  сериях `VmSwap` процесса равен нулю. RSS ниже относится к этим коротким сериям,
  а не к максимальной памяти длинной агентной сессии.

## Проверка инструментов

Инструменты синтетические: `read`, точная замена текста, запуск четырёх проверок
`clamp` и погода с фиксированным ответом «13 °C, дождь». Они работают только с
фикстурой в памяти; пользовательские файлы не исполняются и не изменяются.
Сгенерированная функция допускает только ограниченные выражения min/max,
сравнения и ветвления с return; произвольные вызовы, циклы и импорты отклоняются.

В первой версии стенда не было читаемого исходника тестов и явного рабочего
каталога. Это помешало восстановлению LFM 2.6B после первой неверной оценки
функции. Повторная версия добавляет `/workspace`, относительные и абсолютные
пути, доступный файл тестов и принимает корректные варианты с `if`.
Первоначальную неудачу основной модели не используем для вывода о её качестве.

| Проверка | LFM 1.2B | LFM 2.6B | Spark 1.7B |
| --- | --- | --- | --- |
| Ровно «ГОТОВО» | Пройдено | Пройдено | Пройдено без thinking |
| Два предложения по-русски | Пройдено | Пройдено | Пройдено без thinking |
| Один реальный read отсутствующего файла | Не пройдено, в том числе после уточнения рабочего каталога | Пройдено | Пройдено с thinking |
| Исправить clamp → получить 4 успешных теста | Не пройдено, вместо вызовов выдан текст с кодом | **49,62 с**, 3 вызова, 624 выходных токена | **86,85 с**, 3 вызова, 1213 выходных токенов |
| Погода через один weather | Пройдено | Пройдено | Пройдено с thinking |

Для законченного исправления обе большие модели получили лимит **1536 токенов
на ответ** и native reasoning budget **256**. LFM использовала greedy sampling;
Spark — рекомендованные автором `temperature=1`, `top_p=.95`, `top_k=-1`.
Следовательно, это сравнение практических конфигураций, а не изоляция эффекта
одного параметра. У Spark с лимитом 512 ответ оборвался до редактирования;
увеличение лимита позволило выполнить задачу. Без thinking Spark в первых
пробах имитировал действия текстом и выдумывал погоду.

Повторные отчёты:
[LFM 1.2B, инструменты](../benchmarks/out/model-selection-2026-10-08/lfm12-tools-v2.json),
[LFM 2.6B, исправление](../benchmarks/out/model-selection-2026-10-08/lfm26-repair-v2.json),

Это несколько диагностических сценариев, **не** полный admission suite и не
статистически надёжная оценка общей доли успешных задач.

## Можно ли ускорить основную модель отключением reasoning

Проверены два разных механизма при серверном `--reasoning on`:

1. `chat_template_kwargs.enable_thinking=false` **не отключает** reasoning этого
   GGUF. Ответы всё ещё содержат скрытые рассуждения: 215 и 427 символов в двух
   пробах. Поэтому существующий адаптивный механизм для Qwen нельзя просто
   распространить на LFM по имени архитектуры.
2. `reasoning_budget_tokens=0` действительно убирает reasoning. Ответы заняли
   1,62 и 4,49 секунды, но точный ответ стал «ГОТОВ» вместо «ГОТОВО», а объяснение
   добавило третье предложение «Два предложения.». Автоматическая проверка языка
   пропустила второй ответ; при ручном просмотре ограничение в два предложения
   не выполнено. Включать такой режим по умолчанию оснований нет.

Сырые результаты: [переключатель шаблона](../benchmarks/out/model-selection-2026-10-08/lfm26-fast-chat.json),
[нулевой бюджет](../benchmarks/out/model-selection-2026-10-08/lfm26-budget-zero.json).
Это диагностические примеры, не парный ABBA-тест ускорения; системный контекст
и фоновая нагрузка отличаются от первой серии. Полезный установленный прирост
от кэша префикса описан отдельно в [октябрьском отчёте оптимизации](optimization-2026-10.md).

## Артефакты и воспроизведение

LFM 1.2B взята из [официального GGUF-репозитория LiquidAI](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct-GGUF),
ревизия `8ed288026e23958ad9dfa92d53ed773a8eee7125`, файл
`LFM2.5-1.2B-Instruct-QAD-Q4_0.gguf`, 695755488 байт,
SHA-256 `bb741ebb106d543e9de114b843a3d3d73d51c74b5801e69da2abde821a0cb3e1`.
Лицензия LFM Open 1.0 прочитана; это именно QAD, а не обычная PTQ Q4_0.

Spark взят из [репозитория GGUF stornic56](https://huggingface.co/stornic56/Spark-X2.5-1.7B-GGUF),
ревизия `4772ca2560d056caa592ac9905bcfdd40316ad50`, файл
`Spark-X2.5-1.7B-Q4_K_M.gguf`, 1107457760 байт,
SHA-256 `cbb7568374f2a404fbd5814df7bdd69c062793eb6b903fe701be6ae3ca64e749`.
[Исходная модель XHToken](https://huggingface.co/XHToken/Spark-X2.5-1.7B)
и квантованный репозиторий декларируют Apache-2.0. Авторские оценки Spark
выполнены с thinking; опубликованные баллы нельзя переносить на отключённый режим.
Полной provenance для продвижения в production в этом исследовании не собирали.

Метаданные GGUF, ревизии, размеры и хеши сохранены в
[LiquidAI-artifact.json](../benchmarks/out/model-selection-2026-10-08/LiquidAI-artifact.json)
и [stornic56-artifact.json](../benchmarks/out/model-selection-2026-10-08/stornic56-artifact.json).

Изолированный b10828 собран из commit
`3ad1ba7336986d98592d3e28cafd1a406715351f`, NDK 28.2.13676358, API 28,
статически, `armv8.6-a+dotprod+fp16+i8mm`, OpenMP выключен. Применён существующий
`0002-server-attach-cpu-threadpools.patch`; affinity проверена по потокам процесса.
Все CMake definitions, SHA архива, патча и готового ELF — в
[манифесте сборки](../benchmarks/out/model-selection-2026-10-08/runtime-b10828-build.json).

Пример повтора инструментального сценария после размещения проверенных файлов
на телефоне:

```sh
python3 tools/adb_model_candidate_probe.py \
  --model /data/local/tmp/pideck-model-selection-20261008/Spark-X2.5-1.7B-Q4_K_M.gguf \
  --sha256 cbb7568374f2a404fbd5814df7bdd69c062793eb6b903fe701be6ae3ca64e749 \
  --executable /data/local/tmp/pideck-model-selection-20261008/llama-b10828 \
  --label spark-repeat --mode tools --cases repair --thinking on \
  --temperature 1 --top-p .95 --top-k -1 --max-tokens 1536 \
  --min-headroom .01 --output /tmp/spark-repeat.json
```

Для скорости используется `--mode speed`. Для холодного теста без фоновой нагрузки
оставить стандартный порог `--min-headroom .95`. `adb` должен быть в `PATH`.
Стенд останавливает только собственный сервер и удаляет свой TCP forward.
Каталог моделей, выбранная модель и native-библиотеки установленного APK этими
экспериментами не менялись. Кандидаты остаются отдельными файлами под
`/data/local/tmp/pideck-model-selection-20261008`.
