# Три модели и быстрый запуск — 0.3.0-alpha14

Реализация по итогам [аудита 7 сентября](model-selection-2026-09-07.md).
APK: `dist/pi-deck-0.3.0-alpha14-debug.apk`, versionCode 22, подпись Android Debug.
Веса GGUF скачиваются или импортируются отдельно и проверяются по SHA-256.

## Что изменено

- LFM2.5 2.6B QAD продолжает использовать stock b10092 с уже подготовленными
  исправлениями Android CPU affinity. Эти ELF включены в новую сборку APK.
- K2 Horizon 3.7B Q4_K_M добавлена с отдельным IFM runtime, исправлением reasoning
  parser, закреплённым commit и двумя CPU-вариантами. Скачать плавающий Web UI при
  сборке больше невозможно. Подробности: `third_party/k2-horizon/README.md`.
- Empero Qwen3.8 4B Distill Q4_K_M добавлена со stock runtime, контекстом 8192 и
  адаптивным thinking для простых/сложных запросов.
- Все три профиля показаны первыми в списке моделей. K2 и Qwen остаются ручными
  `CANDIDATE`: незавершённый допуск не меняет автоматический выбор LFM QAD.
- `pideck_edit_text(path, oldText, newText)` упрощает правку для небольшой модели.
  Замена должна быть единственной, основываться на показанном актуальном снимке
  и оставаться в рабочем каталоге, включая разрешение ссылок в пути. Сохраняются
  подтверждение записи, проверка Python, контроль конкурентного изменения,
  атомарная запись, BOM и окончания строк. Старый редактор по якорям доступен
  через дополнительную группу инструментов.
- Prefetch больше не запрещает первое явное чтение и не перенаправляет его в
  другой уже подготовленный файл. Повторные неудачи и вызовы ограничены;
  завершение инструмента переводит следующий запрос в `tool_choice=none`.
  Если провайдер игнорирует это ограничение, Pi прерывает цикл.
- Ссылка вида `GreetingService.greet` распознаётся как метод. Для правки по
  явно названному Python-тесту prefetch может найти определение класса через
  прямой импорт внутри того же проекта. Чтение ограничено по числу и размеру
  файлов, не выполняет код и проверяет границы проекта после разрешения ссылок.
- Новая сессия получает только инструменты первой задачи. Далее набор может
  дополняться без перестановки старых схем. Постоянный промпт сокращён; кеш
  проверяет окончательный запрос после всех преобразований. Изменение контракта
  сбрасывает кеш, чтобы не повторно использовать неподходящее recurrent state.
  Для трёх закреплённых GGUF/runtime переход `auto` → `none` сохраняет кеш:
  равенство фактических префиксов проверяется через `/apply-template`.
  Другие модели и изменения схем, шаблона, сообщений, `required` или конкретного
  инструмента продолжают сбрасывать кеш.
- Настроенное приложение при новом запуске открывает диалог и поле с клавиатурой.
  Карточки «Запустить и продолжить» / «Продолжить» удалены из обычного запуска.
  Во время загрузки можно написать запрос; отправка ставит его в сохранённую
  очередь и запускает модель. При пересоздании Activity текущая вкладка остаётся.
- Обычные системные сообщения используют приглушённый цвет; ответы и ошибки
  сохраняют свои цвета.
- При изменении встроенного runtime APK сам синхронизирует файлы в Termux перед
  использованием агента. SHA-256 охватывает пути и байты всех runtime assets;
  только успешная операция установки именно этого комплекта отмечает его
  актуальным. Старый результат операции из предыдущего APK этого сделать не
  может. Модели, рабочие файлы, пользовательский AGENTS.md и сессии не удаляются.
  Обновление работает и с исправным предыдущим контрактом runtime: обнаруженная
  на телефоне несовместимость проверки alpha13 → alpha14 устранена.

## Проверка на компьютере

- 185 Java unit tests: без ошибок и пропусков.
- 125 Python runtime tests и 57 tests/tools: пройдены.
- 12 расширений / 10 инструментов загружены штатным загрузчиком Pi 0.82.1.
  Проверены успешные точные замены, пустая строка, удаление перевода строки,
  CRLF/BOM, неоднозначность, невидимый диапазон, устаревший снимок, ссылки,
  выход из каталога, отказ в подтверждении и конкурентная запись.
- Pi RPC проверен на настоящем CLI 0.82.1 с синтетическим HTTP/SSE-провайдером:
  streaming, кеш, повтор ответа и остановка провайдера, игнорирующего
  `tool_choice=none`.
- `testDebugUnitTest`, `lintDebug`, `assembleDebug`, `assembleDebugAndroidTest`
  завершены успешно. Lint: 0 ошибок, 13 предупреждений.
- Все 17 native ELF внутри APK совпадают с SHA-256/размерами манифеста.
  Подпись APK проверена `apksigner`; оба ELF K2 p2 воспроизведены второй
  чистой сборкой с идентичными SHA-256.

Логи, проверка подписи, JSON-результат и снимок исходников до изменений:
`build/releases/0.3.0-alpha14/`. Дифф реализации: `changes.patch` в этом каталоге.
Git-метаданные исходного worktree ссылаются на отсутствующий родительский каталог;
изменения сохранены поверх существующих файлов без переинициализации Git.
Сборочные каталоги вынесены на `/mnt/data/pideck-implementation-20260907/`.

## Проверка на SM-S918B

Установлен **alpha14 / versionCode 22** через `adb install -r`, с прежней подписью Android Debug. SHA-256 установленного `base.apk` совпадает с [APK](../dist/pi-deck-0.3.0-alpha14-debug.apk):

`bce9286ed916af4f9a640e675bf6ad82ad966eb99d28368f14005899c644d4af`.

K2 и Qwen 4B импортированы в закрытое хранилище приложения. Каждый прошёл штатную проверку полного SHA-256 и размера и установку с запретом записи. Первая попытка K2 была отклонена из-за прав staging-файла, созданного ADB; после пересоздания файла от UID приложения импорт прошёл. Проверки доступа не ослаблялись.

Автоматическая синхронизация runtime подтверждена при переходе с alpha13 и на окончательном комплекте alpha14. Последнее обновление заняло 9,53 с. Отдельный тест реального окна Android подтвердил фокус поля и видимую клавиатуру при холодном запуске: **0 нажатий для перехода к вводу, 1 отправка для постановки запроса в очередь во время загрузки**. После готовности Qwen ответил точным маркером, очередь очистилась. Сохранение очереди проверено после завершения instrumentation; этот сценарий не выдаётся за отдельное доказательство перезапуска процесса.

У K2 p2 проверен настоящий SSE для `low`, `medium`, `high`: во всех трёх режимах есть окончательный русский ответ без IFM-тегов. Исправлено обнаруженное на p1 смешение medium-рассуждения и окончательного ответа. Шаблоны `auto`/`none` совпали в 2 проверках LFM, 6 K2 и 4 Qwen: начало диалога и продолжение после инструмента, включая доступные режимы рассуждения.

## Скорость и выбранные агентские сценарии

По уточнению пользователя скорость **выше 5 ток/с допустима при высоком качестве**. В таблице указана скорость генерации, измеренная из штатного процесса APK: отдельный прогрев и три валидных ответа по 192 токена, `cache_prompt=false`, seed 42, охлаждение перед каждым запросом и проверка переднего плана каждые 3 с. Порог начала: доступная максимальная частота не ниже 95%, температура CPU не выше 65 °C.

Для сочетания качества и скорости на этом телефоне рекомендую **K2 Horizon 3.7B**: 7/7 выбранных сценариев, медиана генерации 8,67 ток/с. Обе задачи с правкой кода завершены за 158 и 201 с; средняя скорость native-генерации внутри них — 5,01 и 5,29 ток/с, приложение оставалось на переднем плане. Это соответствует уточнённому допустимому порогу в проверенных задачах.

**LFM QAD** быстрее, но прошёл 5/7: при поиске функции сделал три вызова вместо разрешённых двух, а после правильного вызова погоды не завершил ответ (в журнале `token_limit`, затем `tool_markup_as_text`). Обе задачи с правками кода и тестом выполнены; цикл повторного чтения при переименовании устранён. **Qwen 4B** прошёл 7/7, но его две задачи с кодом заняли 246 и 390 с, поэтому в этих условиях выигрыша перед K2 не показал.

Это семь выбранных задач Suite-v2, по одному прогону на модель. Изменения проверялись по содержимому файлов, выполненному тесту и сохранности остальных файлов и внешнего sentinel. Такой набор не завершает полный admission: K2 и Qwen остаются ручными `CANDIDATE`, автоматическая рекомендация LFM QAD сохранена. Q10 проверяет вызов инструмента, ограничение числа вызовов и наличие URL; фактическая точность веб-ответа отдельно не оценивалась.

На Q05 LFM число токенов prefill снизилось с 4144 до 2052 после исправления кеша при завершении инструментов. Полное время двух последовательных прогонов — 126,86 и 79,13 с; оба выполнили одну правку и тест. Это разные APK и последовательные условия устройства, поэтому разница времени не является изолированным A/B-измерением. [Сравнение и SHA обоих APK](../build/releases/0.3.0-alpha14/device/lfm-terminal-cache-comparison.json).

Времена задач включают prefill, генерацию и инструменты. У Qwen в длинном прогоне скорость генерации падала до 4,07 ток/с; наблюдались нагрев и 1,5 ГБ swap. Передний план в его агентском прогоне не записывался. У последующих K2/LFM он проверялся для каждого сценария. В Q10 K2 зафиксирован уход в фон (4,35 ток/с), поэтому этот показатель не описывает скорость активного приложения. Это наблюдения работы приложения, а не изолированный эксперимент по преимуществу архитектуры модели. Один фоновый прогрев Qwen дал 2,50 ток/с и исключён из расчёта; три измеряемых образца валидны. Все исходные результаты, включая исключённый, сохранены.

Android также зафиксировал завершение процесса Termux во время фонового native-замера Qwen. Причина отдельно не изолирована. Следующий обычный холодный запуск приложения автоматически восстановил runtime, native server и Pi без дополнительного нажатия запуска.

Измерения первоначального [аудита](model-selection-2026-09-07.md) относятся к другим артефактам и условиям; новые цифры выше связаны с SHA установленного APK. Проверен телефон с размером страницы 4096 байт; совместимость всех библиотек с устройствами 16 KiB этим прогоном не подтверждалась.

## Завершение проверки

Восстановлены исходная сессия, выбранная пользователем модель `qwen3.8-2b-distill`, профиль `confirm_changes`, настройки idle timeout, срока автономного доступа и питания. Исходная сессия содержит прежние 2 пользовательских и 2 ответных сообщения, без тестовых вызовов; исходные пользовательская и ответная записи консоли сохранены. Консоль штатно хранит последние 60 записей, поэтому старые служебные строки ротируются при запуске; полный исходный снимок оставлен в приватной резервной копии. Размеры и время изменения всех 10 прежних файлов моделей не изменились. На финальной проверке native server и Pi готовы, активных задач и ожидающих подтверждений нет. Временные ADB forwards удалены.

На телефоне прошли 2 теста установки моделей, 3 проверки сохранения операций/черновика/очереди и 1 проверка запуска с клавиатурой и отправки в очередь. Две opt-in проверки восстановления пропущены.
