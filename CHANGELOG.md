# Changelog

Все версии до 1.0 — alpha. Каждая запись описывает поведение, а не список
коммитов.

## Не выпущено

- модель в каталоге может объявить самоспекулятивное декодирование
  (`runtime.speculative`): `draft-mtp` берёт готовые prediction heads из самих
  весов, `ngram-mod` и `ngram-simple` набрасывают продолжение по контексту. Ни
  один режим не грузит вторые веса, поэтому оценка памяти остаётся честной.
  Все профили стоят в `off`: на SM-S918B замер дал 0.96× у `draft-mtp` и 1.05×
  у `ngram-mod` — включать нечего, подробности в
  `docs/speculative-decoding-measurements.md`;
- агент умеет читать веб-страницу, а не только сниппеты: `web_fetch` берёт один
  URL, читает его напрямую и падает на рендерящий прокси только если прямое
  чтение дало слишком мало текста. Компромисс приватности записан в
  `docs/security-model.md`;
- правка файла по якорям: `read` помечает каждую строку как `12:a3`, а
  `pideck_replace_lines` меняет строки по этой метке, вместо того чтобы
  требовать от модели побайтово повторить исходный текст. Устаревший якорь
  отклоняется с указанием актуального, а не применяется не туда. Мутация идёт
  через тот же единственный путь подтверждения, что и `pideck_edit`;
- системный промпт получил разобранные примеры того, когда инструмент вызывать
  не надо: слово-триггер, явный запрет и данные, уже лежащие в запросе;
- отказ якорной правки больше не тупик: он перечисляет действующие якоря вокруг
  нужной строки, чтобы повтор был возможен сразу. На устройстве 2B выдумала якорь,
  получила верный отказ «прочитай заново» — и решила, что инструмент сломан;
- `tests/extensions/run_extension_checks.mjs` грузит все расширения тем же
  загрузчиком, что и Pi, и проверяет якорную правку в CI.

## 0.3.0-alpha8

- запрос можно набирать сразу после открытия деки: на холодном ядре он встаёт
  в очередь, сам запускает прогрев и уходит, как только Pi ответил;
- профиль доступа по умолчанию — `AUTONOMOUS`, режим — `Агент`: команды
  выполняются без отдельного подтверждения каждой. `CONFIRM_CHANGES` остаётся
  в `ЯДРО → Доступ` в одно касание;
- сервер, переживший пересоздание Activity, виден сразу из состояния
  foreground-service, а не после ответа Termux; bridge к нему поднимается сам;
- убран Termux-рейс `server-stop` перед стартом, когда останавливать нечего;
- предупреждение о риске OOM показывается один раз на модель, но реальное
  сообщение Android о нехватке памяти показывается всегда;
- `ЯДРО → Автозапуск` (по умолчанию выключен) грузит модель при открытии деки;
- карточка `BOOT SEQUENCE // 03` больше не мигает на каждом запуске связанной
  деки: probe не сбрасывает подтверждённую связь заранее.

Проверено на Samsung SM-S918B / API 36: холодный старт показывает карточку
ignite вместо link; набранный на холодном ядре запрос ушёл сам через 17.7 с
загрузки модели и вернул ответ на 17.2 ток/с без единого касания;
пересозданная Activity при живом сервисе поднялась в `READY` за две секунды;
в `AUTONOMOUS` агент выполнил `uname -m` без диалога подтверждения.

## 0.3.0-alpha7

- в `ЯДРО → Язык` можно переключить весь интерфейс между русским и английским;
  выбор сохраняется, а тексты пользователя и агента не переводятся и не
  переписываются;
- рядом с каждым завершённым ответом сохраняется его реальная скорость
  генерации: число выходных токенов из provider usage делится на измеренное
  decode-время именно этого ответа;
- сгенерированный provider-конфиг явно запрашивает streaming usage у
  llama.cpp; контракт Termux-рантайма поднят до 12, поэтому старый конфиг не
  может незаметно оставить в UI приблизительную скорость.

| Контур | Результат |
|---|---|
| Android/JVM | unit tests, lint, debug, androidTest APK и release APK на JDK 21 |
| Termux runtime | 54 host-теста |
| Управляемые инструменты | 5 host-тестов |
| Pi RPC | реальный локальный Pi 0.82.1 прошёл protocol smoke |
| Samsung SM-S918B / API 36 | агент записал и выполнил Python; terminal usage дал 1840 output tokens и 13.7 ток/с без `≈` |

> [!NOTE]
> Этот smoke подтверждает доступ агента к записи и Python через approval gate,
> но не гарантирует надёжность длинных цепочек на Qwen3.5 2B. В более строгом
> повторе модель ушла в диагностический цикл; разрешения с TTL при этом, как и
> задумано, закрылись по истечении времени.

## 0.3.0-alpha6

- управляемые `web_search` и `weather` доступны и в профиле `READ ONLY`, не
  открывая shell или запись файлов;
- явный запрос актуальных данных принимается только после успешного сетевого
  инструмента: при попытке ответить из памяти или искать в workspace bridge
  один раз направляет модель к нужному инструменту;
- служебный повтор больше не подписан неоднозначным «восстановлением» или
  «повтором ответа»: интерфейс показывает «Задача продолжается» либо
  «Получаю актуальные данные».

## 0.3.0-alpha5

- в режимах `CONFIRM CHANGES` и `AUTONOMOUS` появились управляемые инструменты
  `web_search` и `weather`; они загружаются из APK явно, даже если
  пользовательские расширения Pi отключены;
- запросы о погоде получают компактные актуальные данные Open-Meteo, а общий
  веб-поиск возвращает ограниченный набор результатов с URL источников;
- ответ, состоящий только из знаков Markdown вроде `**`, больше не считается
  успешным: bridge очищает его, один раз просит модель ответить заново и после
  повторного сбоя показывает честную ошибку.

## 0.3.0-alpha4

- во время печати рядом с контекстом видна сглаженная оценка `≈… ток/с`;
  после завершения Pi заменяет её итоговой скоростью по точному числу выходных
  токенов provider usage;
- показатель остаётся на экране до следующего запроса и озвучивается
  accessibility-службами как примерный или итоговый.

## 0.3.0-alpha3

- режим `Чат` запускает Pi без инструментов и уменьшает служебный контекст для
  быстрых разговорных ответов; `Агент` сохраняет работу с файлами и shell;
- заполнение текущего окна видно в консоли, а перед медленным запросом можно
  сжать историю или начать чистую сессию без потери набранного текста;
- desktop-пороги автосжатия Pi заменены на безопасные значения для локальных
  окон 4k–10k; большие результаты инструментов сокращаются до 12 KiB, а полная
  версия остаётся в приватном `~/.pideck/tool-results`;
- интерфейс показывает этапы подготовки/генерации/инструментов и примерную
  скорость, принимает один следующий запрос в очередь и очищает редактор только
  после подтверждения RPC;
- потоковый ответ добавляется кадрами без полного `setText`, а автопрокрутка не
  возвращает пользователя вниз, если он читает предыдущий текст;
- foreground inference удерживает CPU во время активного turn, экран можно
  оставить включённым в профиле `Скорость`;
- IME-insets и `adjustResize` удерживают поле ввода над клавиатурой Android 15;
- системный промпт редактируется в `ЯДРО` в режимах дополнения или полной
  замены.

## 0.3.0-alpha2

- официальный Android arm64 runtime `llama.cpp b10092` встроен в APK и
  проверяется по размеру и SHA-256 во время каждой сборки;
- `llama-server` работает под UID PI//DECK в foreground-service, поэтому
  открытая дека получает Android `top-app` CPU-set вместо фоновых ядер Termux;
- профиль телефона выбирается автоматически: на Snapdragon 8 Gen 2 decode
  использует 5 быстрых ядер, prompt batch — все 8;
- MTP/speculative decoding намеренно запрещён: на реальном Qwen3.5 2B он был
  медленнее обычного decode;
- GGUF после Android incoming-проверки повторно хешируется и атомарно
  устанавливается с режимом `0400` в приватное хранилище приложения;
- Termux больше не устанавливает вторую копию `llama-cpp`; он отвечает за
  Pi 0.82.1, shell, сессии и authenticated RPC;
- контракт `server-adopt` принимает app-owned сервер только после точного
  model/API-key health-check; быстрый restart RPC исправлен для TCP
  `TIME_WAIT`;
- на Samsung SM-S918B direct ADB smoke дал 16.13 ток/с внутри сервера и
  15.54 ток/с end-to-end при 292 output tokens;
- упавший инструмент больше не роняет весь turn: агент читает ошибку и берёт
  следующий вызов, а `TURN_FAILED` остаётся только за ошибкой модели и
  падением child-процесса.
